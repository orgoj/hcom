# hcom-dashboard

Native Rust GUI for visualizing and managing `hcom` agents, instances, and message flows. Built with `egui`/`eframe`.

`hcom-dashboard` integrates interactive 2D node-link graph visualization with full agent fleet management:
- **Layout**: the window has its own icon (three agent nodes in CLI colors, drawn in code), shown by the window manager in the title bar and the taskbar; the graph canvas fills the upper left; the right detail panel holds the tabs of the selected agent (Summary, Report (F9), Screen (F5), Transcript (F6), Sessions, Events (F7), Log (F8), Config) and the graph-wide Legend tab. The top bar rows wrap whole control groups instead of clipping them; its second row holds View, Layout, Edges and Width. Section labels (`GRAPH FILTER` and `TABLE FILTER` on the filter strips, `VIEW`, `LAYOUT`, `EDGES`, `WIDTH`, and `WINDOW`, `LAST` in the window row) are blue uppercase text, set apart from the controls they introduce. Progress of a running action (`⏳ …`) shows at the end of the action toolbar. The agent table spans the full window width at the bottom. The toolbar view selector switches between `Both (F4)`, `Graph`, and `Table` modes (pressing F4 toggles between Both and Graph modes); `Detail` shows or hides the detail panel; an F5–F9 key opens the detail panel on its tab, and Alt+Left/Right select the previous/next tab (no wrap-around). A new ERROR line in the Log while another tab is open puts a red dot on the Log tab; opening Log clears it. Equal consecutive Log lines show once with their count (`(×6)`). Screen, Transcript, Events and Log open at their end and keep the newest lines in view as content arrives; scrolled up, the view stays put until you scroll back to the end (Sessions lists the newest session first). F-keys and Alt+arrows act even while a text field has focus. Drag the table top edge or the detail panel left edge to resize (double-click resets to 30 %); a size is stored as a fraction of the window, so it stays put until you drag again and keeps its proportion on another screen. Panel content never changes the size. Widen the detail panel for the Screen tab (terminal lines scroll horizontally, the inject bar stays at the panel bottom). The canvas keeps at least 150 px of height and 200 px of width while the panels need more; the panels never go below 80 px (table) and 240 px (detail panel), so in a very small window the canvas gives way first. The stored fraction stays for the next larger window.
- **Sessions tab**: the sessions of the selected agent (running or stopped) that overlap the message time window, newest first. The header stays above the scrolling cards, under a rule: `24 sessions` when the window shows all of them, else `1 of 171 sessions in the time window`; with none in the window `No sessions in the time window (N total)` and, when N > 0, `Show all`, which sets the window to All. A card is compact and fits the detail panel at its minimum width (a long title ends with … and shows whole on hover; the buttons wrap): line 1 is its title when known (Claude: the last `/rename`, else the AI title; Codex: the thread name), else a weak `session <id8>`, with `running · <live duration>` or `ended · <duration>` on the right; line 2 names the CLI with the model and reasoning effort it was launched with (`codex · gpt-5.6-terra · medium`, from `--model`/`-m`, `--effort` and `-c model_reasoning_effort=…` in the launch arguments; a hover shows all launch arguments, from the `stopped` snapshot or, for the running session, `hcom list --json`); line 3 joins start – end (the end date only when it differs), who launched it (an agent, `user`, or `handoff`), why it ended (`handoff` when it was handed off), transcript size and, under a title, the short session id with ` · `; then `continues from session …` / `handed off to session …` along a handoff chain (a link when that session is listed: a click scrolls to its card and highlights it for 1.5 s), the directory (home as `~`), and message partners with sent (↑) and received (↓) counts during the session. `Resume` and `Fork` open the Start dialog for `hcom r <session id>` / `hcom f <session id>` with the session directory and an optional prompt (`--dir` only when changed): a one-line hint says what it does (Resume continues the session in a new terminal, Fork starts a new session and keeps the original), a weak monospace line shows the command live (the prompt as `"…"`), and the primary button is named `Resume` or `Fork` (Enter too; Tab goes dir → Browse → prompt → primary → Cancel; Escape cancels); Resume is disabled while the agent runs (the Sessions header then says `agent is running — Resume is off (Fork works)`), and both are disabled without a session id, without the transcript file, or for a tool that cannot be targeted by session id (Resume: claude, codex, gemini, opencode, kilo; Fork: claude, codex, opencode, kilo); the tooltip says why. `Transcript` shows that session file in the Transcript tab (also for a stopped agent) until another tab or agent is chosen; its header names the session (title, start, short id) with the file path in the tooltip. `Show in graph` sets the message window to the session interval in whole minutes, start rounded down and end up, the same minutes the card shows (a running session: a live window from its start minute) and highlights the card; the Sessions header then shows `Graph shows session … [Restore window]`. `Restore window` (or Escape on the Sessions tab) brings back the window and list position from before the first `Show in graph`; any other window change (preset, slider, text field, `Live`, `Last`) ends the offer.
- **Summary metrics**: under the screen lines the Summary tab sums up the other tabs of the selected agent, one row each: Screen (lines, and whether the Summary shows them all), Transcript (exchanges shown of total, size, `truncated` while hcom elides text or tool details), Sessions (`N sessions` or `N of M sessions in the time window`, following the message window), Events (count, `latest 50 loaded` at the load limit) and Log (lines, errors). Selecting an agent on Summary loads Screen, Transcript, Sessions and Events in the background and again on every data refresh; a value not loaded yet shows `…`, and a stopped agent shows `— (stopped)` for Screen, Transcript and Events.
- **Transcript tab**: the last 100 exchanges of `hcom transcript` for the selected running agent (or of a session file opened from Sessions). The toggles `Full` (complete assistant responses, `--full`) and `Detailed` (tool I/O, file edits, errors, token usage, `--detailed`) above it reload the transcript with that flag, also a session transcript; they apply to every agent and are kept in `dashboard-state.json`.
- **Filters**: the graph and the table each have their own filter strip, the graph one above the canvas (`GRAPH FILTER`), the table one above the column header (`TABLE FILTER`): a search field (agent, dir, tool, …), `Running only`, `Blocked only`, `Hide disabled` (on by default) and `Hide ad-hoc`, and the panel's `Shown N / M`. Both filters, including the search text, are saved in `dashboard-state.json`. Graph `Running only` keeps the agents running now and those that ran at any time of the message time window (a session from its `created` to its `stopped` event overlaps the window; with `All`, every agent with a session in the loaded history); table `Running only` keeps the agents running now (the message window does not apply to the table). `/` focuses the table search and Alt+X clears it. `Kill group` → `Filtered (N)` kills the running agents the table filter lets through. A table row the graph filter hides stays selected (table, detail panel); the graph just does not highlight it.
- **Config tab & stopped agents**: When an agent is stopped, the Screen, Transcript, and Events detail tabs show an explicit stopped notice with a `📋 View Config` shortcut to switch to the Config tab. The Config tab displays the agent's catalog attributes from `agents.json` (CLI tool, description, directory, model, reasoning effort, groups, roaming configuration, skills, instructions, status columns) with parameter preview controls for future editing, while adhering to catalog isolation (catalog provenance paths are not exposed).
- **Agent count**: each filter strip ends with `Shown N / M` (agents its search and filters let through / all known instances and catalog agents; the status counts in the top bar cover all), explained in its tooltip. The agent Summary leaves out empty fields; Status Age uses the format of the `since` column. For a running instance it ends with the last 8 lines of its screen, refreshed like the Screen tab; Inject is on the Screen tab only.
- **Table**: Real-time listing of active instances and catalog agents with configurable columns and search/filtering. When fetching the agents fails (the reason is in the Log) and there is nothing to show, the table body and the canvas centre say `Agent data could not be loaded — see Log (F8)` in red until the next successful fetch. A click anywhere in a row selects it (one band over the whole row) and its graph node; Up/Down select the next or previous row in the shown order like a click and scroll it into view, Home/End the first/last row and PageUp/PageDown move by the rows the table shows (not while a text field has focus, except Up/Down in the table search field; Alt+Up/Down act wherever the keyboard is; the graph has no keyboard control); selecting a node in the graph also scrolls its row into view, and so does a selected row that moves (sort order, a started agent); otherwise your scroll position stays. The selection follows the instance name (else the agent name); when the selected row leaves the table (e.g. after Kill), the row now at its place in the shown order is selected (the last row when the table got shorter), like `contrib/hcom-gui`, so Delete can kill the next one; when that is the stopped row of the killed instance's own catalog agent, the next row is selected (the previous one at the end); a row that loses its instance (an instance named like its catalog agent) counts as gone too, except after Restart, which keeps the selection until another row is selected or the row is killed; while a started instance is awaited, or for a graph node the table never showed, the selection stays. `/` (while no text field has the keyboard) focuses the table search field. A double-click on a running agent's row, or Enter on the selected one (not while a dialog or another text field than the table search has the keyboard), attaches it like a double-click on its node; on a stopped catalog agent it opens the Start dialog. Shift+Enter (same conditions) opens the Start dialog for the selected row's catalog agent, also while it runs, like `s`; on an ad-hoc instance it does nothing. Quick select: `/`, a part of the name, Up/Down if needed, Enter; when the search text changes and the selected row is no longer shown, the first shown row is selected. Escape leaves the search field and keeps the filter. The table lists the agents its own filter strip lets through (see Filters); cells longer than 300 px end with … and show the full value in a tooltip; a click on a column header sorts by it (`status:status` by what needs you first: `blocked`, `error`, `NEEDS_USER`, `DONE_FOLLOWUP`, `DONE`, other listening agents, `active`, other states, stopped agents; within one state the oldest `since` first; the second click reverses the whole order); the header stays at the top while the rows scroll vertically and moves with the columns horizontally. Row text is colored by state like `contrib/hcom-gui`: active green, blocked orange, `needs_user` (Idle column) blue, error red, stopped catalog agents gray, disabled ones light gray and struck through (lighter shades in the dark theme); the selected row uses the selection text color. `Columns…` (end of the action toolbar) chooses the shown columns and their order, like `contrib/hcom-gui`: every column incl. `status:<name>` (values from the `STATUS` block of the agent's last reply; `status:status` shows a running agent's live state instead, e.g. `active` or `blocked`, unless it is `listening`) is listed, shown ones first; a click or Up/Down picks one, Space or its box toggles it, Ctrl+Up/Down or `Up`/`Down` move it, Enter or `OK` applies (at least one column stays shown), Escape or `Cancel` closes; the choice is saved in `dashboard-state.json`, `Reset` returns to the default columns.
- **Graph styling**: dashed spawn edges (parent → child), solid message edges, a CLI-colored ring per node, context window fill from the bottom (green < 70 %, amber 70–85 %, red > 85 %), a dashed outline for roaming agents, and the agent name below the node on a canvas-colored background. When two names overlap, the name of the agent with fewer messages in the window is hidden; the hovered agent, the selected agent and its neighbours always keep their name. While an agent is selected, it, its direct neighbours and its edges keep full color and every other node, edge, badge and name is dimmed to a quarter. The Legend tab of the detail panel explains the status border colors, CLI ring colors, the roaming outline and the edge styles, listing only those visible in the current (filtered) graph.
- **Layout modes** (top bar, persisted): *Hierarchy* arranges the spawn tree in layers (a node's parent is its `parent_name` for Claude subagents, otherwise the agent that launched its current session, `by` of the last `batch_launched` life event, kept across a `hcom handoff` relaunch; sessions the user launched are roots) (parents centered over children, message springs act horizontally; when the root layer is wider than a fixed 1600×900 reference area, roots without children wrap into rows below the trees, shaped to fit that area; the window size never changes the arrangement); *Cluster* is force-directed with message springs scaled by ln(1 + count), so heavy communicators sit together; *Manual* stops the simulation and nodes move only by dragging. A drag alone stores nothing; `Pin Position` in a node's right-click menu, or Shift+click on the node, pins it (a light dot on its upper right), so it keeps its place in every mode and after a restart, and `Unpin Position` (or another Shift+click) releases it; dragging never changes the pin. New nodes appear next to their parent or a message partner, otherwise on a spiral; a collision radius keeps nodes from overlapping. While you drag a node, the others adapt live; at start, after a new agent or message pair appears, and when you release a node, the layout first computes where every node comes to rest and then moves each one there in a straight, eased glide (no swinging back and forth). `Reset` (right of `Fit`; disabled in *Manual*) rearranges every unpinned node from scratch in the current mode, agents without any edge in rows next to the others in *Cluster*; after a Reset or a switch between modes the nodes glide to the new arrangement in 4 s (ease in and out) and then rest. Pinned nodes stay; unpin them to rearrange them.
- **Fit to content**: `Fit` (top bar, right) zooms and pans so every shown agent, its rings and its label fit the canvas with a 5 % margin (up to 400 %). Without a saved view, or when the saved view shows no agent, the view fits itself once at start (up to 100 %); it never does so in *Manual* or while a mouse button is held. Resizing the canvas (window, table or detail panel) never moves the agents or changes the zoom: the point of the graph at the canvas center stays at the center. A triangle on the canvas edge, in its status color, points to every shown agent outside the view.
- **Theme**: the button right of `Fit` (top bar) cycles `💻 Auto` → `☀ Light` → `🌙 Dark`; the choice is saved in the state file. *Auto* follows the theme the windowing system reports; where it reports none (e.g. LXQt on X11), it reads the desktop config once at start: the `window_color` of the LXQt `[Palette]` in `lxqt/lxqt.conf`, else `gtk-3.0/settings.ini` (`gtk-application-prefer-dark-theme`, or a `gtk-theme-name` containing `dark`), both under `$XDG_CONFIG_HOME` or `~/.config`. Without any source it is dark.
- **Message time window**: presets (5m, 15m, 1h, 6h, 24h, All), an interactive two-handle range slider over retained history (left thumb drags start time, right thumb drags end time; boundary snapping activates All or Live), a Live toggle, a text input field accepting relative spans (e.g. `1h`, `15m`, `all`) or absolute intervals (e.g. `12:00 - 13:00`, `2026-11-03 12:00 - 2026-11-03 13:00`, `all - 13:00`, `12:00 - now`; invalid inputs are visibly marked in red leaving the interval untouched), and a "Last N msgs" limit (0 shows `no limit`). All times are local; the text field reads and shows times without an offset (`12:00`, `2026-11-03 12:00`) as local time (an RFC 3339 time with an offset or `Z` is taken as given), with seconds only when they are not 0. The slider tooltip names the window end: `now` while Live is on, otherwise the end time. Edge badges (`1 msg`, `N msgs`), edge thickness and the conversation detail follow the window; a badge shows from 2 messages on, or on any edge of the selected or hovered agent; edges without messages in it are dimmed but stay clickable. The header shows the range in local time; its tooltip shows it in UTC. At start the graph loads every message of the current hcom database (archived sessions excluded) and keeps all of them, so counts and history are exact for any range; only an explicit "Last N msgs" limits the number of messages, in Live too. The conversation detail lists the newest 50 messages of the window. In a Live window, an edge flashes in the selection color for 0.4 s when a new message arrives on it (not for the history loaded at start).
- **Hover tooltip**: hovering a node shows a card beside it: right, left, below or above, the first position that fits the canvas without covering the node. The card is as wide as its content (at most 360 px) and fades out when the pointer leaves the node. It is hidden while dragging, with a mouse button pressed, and while a menu or dialog is open. Fields come from the `tooltip` config key, using the same keys as `report` (including `status:<name>`), in the listed order; the default is `["status", "detail", "cli", "since", "age", "dir", "unread", "context"]`, and `[]` turns the tooltip off. Empty values are skipped, and a multi-line value shows its first line with `…`; `dir` shows the home directory as `~` and a path longer than 48 characters with `…` in the middle.
- **Durations**: `since`, `age`, `runtime`, the Summary Status Age and the session length on Sessions cards follow the `time_format` config key (read at start), default `"hh:mm"` (`01:23`, 51 h 15 min as `51:15`). Tokens: `d` days, `hh`/`h` hours (two digits / unpadded), `mm` minutes, `ss` seconds; other characters are literal, and the largest unit in the format holds the whole rest (`"d hh:mm"` gives `2 03:15`). `"short"` shows only the largest unit (`2d`, `1h`, `5m`, `30s`).
- **Usage columns**: `context` (tokens and percent of the context window of the latest model call) for Claude and Codex, and `quota` (Codex primary rate limit, used percent), read from the last 1 MiB of the instance's transcript on each table refresh. Claude transcripts record no window size; 1M is assumed.
- **Idle column**: once a listening instance has been listening for `idle_seconds` (default 10) and the column is shown, `contrib/idle-classifier/idle_check.py` classifies it as `needs_user`, `waiting` or `done` (`-` none, `…` queued), once per listening period; at most one check (up to 32 agents, 180 s timeout) runs at a time. Remote instances report no listening age: they count from first sight. Errors appear in the command log as idle_check's own error line only.
- **Actions**: Start catalog agents, Send messages, Attach/focus terminal panes, Restart, Kill individual agents or groups, and launch external tools (`open_with`; an entry's `key`, e.g. `"g"`, is a typed character that runs it for the selected agent like its button, not while a text field has the keyboard or a dialog is open). Built-in keys for the selected agent, under the same conditions and only while the button is enabled (its tooltip names the key): `s` Start…, `m` Send…, `r` Restart, Delete Kill (both with their confirmation), Ctrl+C copies the agent name to the clipboard (text selected with the mouse is copied instead); an `open_with` entry with the same `key` wins over `s`, `m` or `r`. An action error shows at the top of the detail panel only for the agent it belongs to (an error without an agent: the agent selected when it came). `✖` or Escape (not while a dialog, a context menu or a text field has the keyboard) dismisses it; a failed Screen, Transcript, Events or Sessions load of an agent disappears by itself once the same load succeeds (e.g. after the agent finished starting).
- **Dialogs** (Start, Send, the Kill/Restart/Kill group/command confirmations) are modal: centered on the window over a dimmed backdrop, they block the rest of the app (Tab cycles only their own fields, global shortcuts are off) and Escape closes them. On opening, the first field has focus (Send: the message), a confirmation focuses `Cancel`.
- **Start dialog** (`Start...` for a selected catalog agent, or a double-click/Enter on a stopped one): the fields of `contrib/hcom-gui`: `resume` (`--resume`, `--continue` when another CLI is chosen), `name` (gets `<agent>__` on focus; left unchanged it counts as empty), `dir` (`Browse…` opens the system folder chooser through xdg-desktop-portal), `cli` (a choice of the CLIs found on PATH), `model` and `reasoning` (any text; `▾` offers the catalog models and the reasoning levels), `prompt`; prefilled from the catalog entry, and an answer equal to its prefill passes no flag. Enter (Shift+Enter: newline in the prompt) runs `hcom agent <agent> ...`, Escape cancels. The started instance (named by `name`, else after the agent) is selected once the table shows it, unless you selected another row meanwhile or the command failed.

## Configuration & State Persistence

`hcom-dashboard` keeps its configuration and state in its own files:

### Configuration
`~/.hcom/dashboard.json` (same keys as `contrib/hcom-gui`'s `gui.json`). If it is missing or its syntax is corrupt, built-in defaults are used.

### State Persistence
User layout preferences (whether the window is maximized and its last normal size and position, restored at the next start, so un-maximizing returns to them; a normal size or position counts once it held for 0.5 s, so the frames of a maximize transition never replace it; a window manager that ignores the maximized flag of a new window is asked again once the window is up, and the saved flag stays until the window reports maximized or 2 s pass; table and detail panel visibility, active detail tab, table height and detail panel width as window fractions, active filters, sort order, layout mode, the message window span and limit, zoom, pan, and the positions of pinned nodes) are saved to:
```
~/.hcom/dashboard-state.json
```

- A pinned node's position (`pinned_positions`) is stored by instance name when it is pinned and when a drag of the pinned node ends; the 500 most recently stored pins are kept. A pinned node starts there and the simulation does not move it in any mode, *Hierarchy* included.
- Zoom, pan and the split fractions are saved 1 s after the last change (no mouse button held) and on a normal exit; a kill can lose the last second.
- Invalid values are dropped or clamped on load and before saving (non-finite numbers, zoom outside 15–400 %, split fraction outside 0–1 (dropped) or outside 5–95 % (clamped), an unknown detail tab becomes Summary); a bad position entry is skipped without rejecting the file, and an unreadable `dashboard-state.json` falls back to defaults.
- Several open `hcom-dashboard` windows share the file: each save writes a unique temp file and renames it, so the file stays valid and the last writer wins.

## Tool Execution & Placeholders

- **External Launchers (`open_with`)**: Run asynchronously in detached mode (`SpawnDetached`) without blocking the GUI or background sync workers. Child processes are automatically reaped.
- **Custom Commands (`commands`)**: Run synchronously bounded via `RunCommand` with a 30-second timeout, with output and exit status captured and displayed in the Log tab.

### Supported Placeholders
Commands support the following token substitutions:
- `{dir}`: Agent working directory.
- `{instance}`: Live instance name.
- `{agent}`: Catalog agent name.
- `{terminal}`: Terminal preset or emulator.
- `{pane_id}`: Terminal pane identifier.
- `{herdr_workspace}`: Herdr workspace.
- `{herdr_tab}`: Herdr tab name.

Any unrecognized `{...}` placeholder is rejected with an error dialog.

### `if_exists` Guard
An `open_with` entry can specify an `"if_exists": "{dir}/..."` path. The button is only enabled/shown when the target file or directory exists on disk.
